# CI/CD: FastAPI → Docker → GHCR → деплой по SSH

Учебный проект по автоматизации доставки кода: приложение на FastAPI упаковывается в Docker-образ, публикуется в GitHub Container Registry и автоматически разворачивается на сервере по SSH. Всё происходит по push в `main`, без ручных шагов.

Репозиторий небольшой, но это не заготовка: пайплайн рабочий и собирается из двух последовательных джобов.

## Работающий сервис

Приложение развёрнуто и отвечает:

| Что | Адрес |
|---|---|
| Приветствие | http://185.105.116.187/api/time/ |
| Время UTC | http://185.105.116.187/api/time/time |
| Дата | http://185.105.116.187/api/time/date |
| Дата и время | http://185.105.116.187/api/time/datetime |
| Конвертер часовых поясов | http://185.105.116.187/api/time/convert?time_str=2026-11-10T12:00:00&from_tz=Europe/Moscow&to_tz=America/New_York |
| Swagger UI | http://185.105.116.187/api/time/docs |

Развёрнуто через `docker compose` на VPS, наружу выходит только nginx: контейнер слушает `127.0.0.1:8000`, публичного порта у него нет. Префикс `/api/time/` срезается проксированием, поэтому uvicorn запущен с `--root-path /api/time` — иначе `/docs` ссылался бы на `/openapi.json`, которого на верхнем уровне нет.

## Что здесь главное

Ценность проекта — не приложение, а `.github/workflows/deploy.yaml`: полный путь от коммита до запущенного контейнера на удалённом сервере.

```
push в main
    │
    ├─ JOB test (ubuntu-latest)
    │   ├─ checkout
    │   ├─ docker build
    │   ├─ docker run
    │   ├─ ожидание ответа сервиса (до 20 с)
    │   ├─ smoke-тест: /, /time, /date, /datetime,
    │   │   /convert (12:00 MSK = 04:00 EST), /docs, /openapi.json
    │   └─ логи контейнера при падении
    │
    └─ JOB deploy (needs: test, только для main)
        └─ SSH на сервер под пользователем deploy:
            └─ срабатывает deploy.sh (ключ ограничен этой командой):
                ├─ отказ при незакоммиченных изменениях
                ├─ git reset --hard на origin/main
                ├─ docker compose up -d --build (если коммит изменился)
                ├─ ожидание healthcheck
                └─ проверка эндпоинтов через nginx
```

## Почему не GHCR

Изначально образ собирался в GitHub Actions и публиковался в GitHub Container Registry. Для этого стенда схема не подошла по двум причинам:

1. **Пакет GHCR приватный по умолчанию.** Чтобы сервер мог сделать `docker pull`, ему нужен логин — то есть `GITHUB_TOKEN` в скрипте на сервере. Это ровно тот риск, который описан в разделе «Замечание по безопасности» ниже: токен виден в `ps`. Делать пакет публичным ради учебного сервиса тоже нежелательно.
2. **`docker run -p 8000:8000` открывает порт наружу** мимо nginx, а префикс `/api/time` при этом теряется.

Поэтому сборка перенесена на сервер (`docker compose build`), а в Actions осталась проверка: образ собирается и прогоняется smoke-тест до того, как деплой вообще начнётся. GHCR из пайплайна убран намеренно, а не по недосмотру.

## Что показывает проект

| Практика | Где видно |
|---|---|
| Docker-образ приложения | `Dockerfile`: `python:3.11-slim`, установка зависимостей отдельным слоем, запуск через uvicorn |
| Проверка до деплоя | job `test`: сборка, запуск, smoke-тест эндпоинтов |
| Порядок джобов | `needs: test` — деплой не стартует, если проверка упала |
| Защита от деплоя с ветки | `if: github.ref == 'refs/heads/main'` |
| Ограничение ключа | в `authorized_keys` у ключа `command="/srv/test-actions/deploy.sh"`: по нему нельзя выполнить ничего, кроме деплоя |
| Отдельный пользователь | `deploy`, не `root`; в группе `docker`, владеет каталогом проекта |
| Идемпотентность | повторный запуск без изменений не пересобирает образ |
| Проверка результата | ждёт `healthy` и дёргает эндпоинты через nginx, а не только в контейнер |
| Секреты вне репозитория | `HOST`, `USERNAME`, `SSH_KEY`, `PORT` — в GitHub Secrets |
| Чистка сервера | `docker image prune -f` после деплоя |

## Приложение

`app/main.py` — FastAPI-сервис «Time Server API»: четыре эндпоинта, выбран нарочно простым, чтобы внимание было на пайплайне, а не на бизнес-логике.

| Метод | Назначение |
|---|---|
| `GET /` | приветствие |
| `GET /time` | текущее время UTC |
| `GET /date` | текущая дата UTC |
| `GET /datetime` | дата и время UTC одной строкой |
| `GET /convert?time_str=&from_tz=&to_tz=` | конвертация времени между часовыми поясами (`Europe/Moscow` → `America/New_York`) |

Swagger доступен на `/docs`.

## Запуск локально

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Или в Docker:

```bash
docker build -t time-server .
docker run -d --name fastapi-app -p 8000:8000 time-server
```

Или через compose — так развёрнуто на сервере, флаги не нужно помнить:

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f
```

В `docker-compose.yml` зафиксировано всё, что легко забыть: порт только на `127.0.0.1`, `--root-path /api/time`, healthcheck, ограничение логов и `restart: unless-stopped`.

Проверка:

```bash
curl http://localhost:8000/time
curl "http://localhost:8000/convert?time_str=2025-03-30T12:00:00&from_tz=Europe/Moscow&to_tz=America/New_York"
```

## Что нужно, чтобы пайплайн заработал у себя

1. Форкнуть репозиторий или скопировать `.github/workflows/deploy.yaml` и `deploy.sh`.
2. В **Settings → Secrets and variables → Actions** добавить:

   | Секрет | Значение |
   |---|---|
   | `HOST` | IP или домен сервера |
   | `USERNAME` | `deploy` (не `root`) |
   | `SSH_KEY` | приватный ключ целиком, вместе со строками `BEGIN` и `END` |
   | `PORT` | порт SSH, обычно `22` |

3. На сервере: установлен Docker и Compose, есть пользователь `deploy` в группе `docker`, каталог проекта принадлежит ему.
4. В `~deploy/.ssh/authorized_keys` — публичный ключ с ограничением:

   ```
   command="/srv/test-actions/deploy.sh",no-port-forwarding,no-agent-forwarding,no-X11-forwarding,no-pty ssh-ed25519 AAAA... github-actions-deploy
   ```

   Без `command=` ключ даёт полноценный доступ к серверу; с ним — только деплой. Проверка: любая команда по этому ключу всё равно запускает `deploy.sh`.

5. `deploy.sh` на сервере должен быть исполняемым и принадлежать `deploy`:

   ```bash
   chmod +x /srv/test-actions/deploy.sh
   chown deploy:deploy /srv/test-actions/deploy.sh
   ```

**Важно, если разворачиваете за nginx.** Порт приложения должен слушать только `127.0.0.1`, а префикс адреса задаётся `--root-path`. Оба условия зафиксированы в `docker-compose.yml` — им и пользуется `deploy.sh`.

## Замечание по безопасности

Пайплайн не передаёт на сервер никаких токенов: образ собирается на месте, GHCR не используется. Единственный секрет, который покидает GitHub, — приватный SSH-ключ, и он ограничен одной командой на стороне сервера.

Если вернётесь к схеме с GHCR, помните: `echo ${{ secrets.GITHUB_TOKEN }} | docker login ...` в удалённом скрипте подставляет токен в командную строку до отправки, и он виден в `ps` другим пользователям машины.

## Ограничения

- Приложение не хранит состояние: только чтение системного времени.
- Отката нет: если новый образ не запустится, `deploy.sh` упадёт с ненулевым кодом, но предыдущий контейнер уже пересобран. Для продакшена нужен возврат к предыдущему тегу.
- Зависимости в `requirements.txt` не закреплены по версиям: повторная сборка через несколько месяцев может дать другие версии FastAPI и Starlette.
- Сборка идёт на сервере: на слабой машине деплой занимает время и нагружает CPU. GHCR-схема была бы быстрее, но требует токена или публичного пакета.
